# Domain documentation

Use one shared domain context for the Flutter frontend and backend.

## Locations

- Vocabulary: `GLOSSARY.md` at the repository root.
- Architecture decisions: `docs/adr/`.

Before investigating an area, read the glossary and relevant decisions
if present. Continue quietly when they are absent. Create documentation
as terminology and decisions are resolved, rather than generating empty
files during setup.

## Usage

Use established glossary terms consistently in specifications, tickets,
code discussions, and tests. Check unfamiliar terminology against the
project before introducing it; capture resolved additions through
domain modeling.

If a proposal conflicts with an architecture decision, identify the
decision and explain why it should be reconsidered.
